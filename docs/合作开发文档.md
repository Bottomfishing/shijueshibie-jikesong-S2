# 麦浪精灵（Wisp Field）三人合作开发文档

> 目标：将现有项目重构为一个可稳定演示、约 6 分钟完成的单场景互动体验。
>
> 技术基线：Vite + TypeScript + Three.js + MediaPipe Hand Landmarker。

## 1. 项目目标与范围

### 1.1 体验目标

玩家站在摄像头前，通过移动手掌、张开手掌和捏合手指，唤醒麦田中的精灵，带它采集花朵，穿过逐渐打开的麦海，最后在海边完成一次风与光的高潮。

核心原则：

- 单场景、单主角、单条情绪曲线；
- 零文字教程，使用世界反馈完成引导；
- 摄像头不可用时，鼠标模式必须能完整演示；
- 6 分钟内可以从开始玩到结尾，并且可以一键重来。

### 1.2 本轮明确不做

- 不扩展第二个完整场景；
- 不增加复杂背包、任务、对话或多结局系统；
- 不在后期新增核心玩法；
- 不让流程判断散落在世界对象内部。

现有帆船和“第二章”代码可以保留为结尾演出钩子，但本轮只把登船或海边高潮作为结尾，不继续进入第二关。

## 2. 6 分钟体验流程

| 时间 | 阶段 | 玩家行为 | 世界反馈 | 完成条件 |
|---|---|---|---|---|
| 0:00–0:40 | 静止 | 试探性抬手、移动 | 冷灰麦田轻微回应，精灵沉睡 | 检测到有效移动，或超时自动进入下一阶段 |
| 0:40–1:40 | 唤醒 | 挥动手掌 | 麦浪分开、精灵醒来并靠近 | 玩家累计移动达到阈值 |
| 1:40–3:00 | 建立关系 | 带精灵靠近并捏合采集 3 朵花 | 花朵生长、精灵跟随、色调变暖 | 3 朵花全部采集，或阶段超时兜底 |
| 3:00–4:20 | 向北探索 | 沿麦田通道带精灵向北移动 | 北方麦海打开，镜头从全景转为跟随 | 到达北方触发区 |
| 4:20–5:30 | 起风与海 | 张开手掌持续起风 | 雾气散开，金色海面和栈桥显现 | 风力充能完成 |
| 5:30–6:00 | 最终高潮 | 走到海边或登船 | 麦田、精灵、海面达到最亮状态，音乐收束 | 演出完成后显示重玩入口或自动重置 |

所有阶段都必须有最大时长和鼠标兜底，不能因为玩家没有完成动作而永久卡住。

## 3. 三人职责

### A：交互与流程负责人

负责“玩家的动作被正确理解”。

- `src/input/`：摄像头、MediaPipe、鼠标/触摸兜底、滤波和坐标映射；
- `src/director/`：6 分钟状态机、阶段切换、超时和重置；
- `src/types.ts`：输入和流程公共类型；
- `src/config/story.config.ts`、`src/config/input.config.ts`；
- 负责摄像头拒绝、手部丢失、重复捏合等异常路径。

交付标准：手离开画面不会导致世界瞬移；摄像头失败能自动切鼠标；两种输入都能走完整流程。

### B：视觉与世界负责人

负责“世界对动作有漂亮反馈”。

- `src/world/`：麦田、精灵、花朵、环境、海面、栈桥；
- `src/shaders/`：麦浪、光晕和相关材质；
- `src/config/world.config.ts`、`src/config/render.config.ts`；
- 帧率、实例化渲染、Shader 参数和视觉调校。

世界模块只消费导演传入的状态和输入，不自行决定流程阶段。例如 `WheatField` 不判断“花是否采完”。

交付标准：手部反馈在 1 秒内可见；精灵不是机械贴手；花朵采集有明确反馈；目标设备上帧率稳定。

### C：演出、体验与发布负责人

负责“把功能组织成完整的 6 分钟体验”。

- `src/show/`：镜头、转场、音效、最终演出；
- `src/ui/`：无文字引导、调试面板、现场模式；
- `src/core/` 的装配和演出调用；
- `main.ts`、构建、录屏、现场设备和回归测试；
- 负责最终体验验收和 `main` 发布。

C 不作为“其他所有事情”的接盘人；新增演出能力应优先放到独立模块，避免三人同时修改 `App.ts`。

## 4. 模块边界与公共接口

### 4.1 输入层

输入层只输出标准化 `PointerState`，世界层不得直接依赖 MediaPipe 关键点：

```ts
interface PointerState {
  active: boolean
  world: THREE.Vector3
  velocity: THREE.Vector3
  energy: number
  spread: number
  grab: number
  traveled: number
}
```

### 4.2 导演层

导演层只输出世界意图，不直接操作具体 Mesh：

```ts
interface WorldIntent {
  phase: 'dormant' | 'awakening' | 'bonded' | 'journey' | 'finale'
  warmth: number
  windStrength: number
  interactionGain: number
  cameraMode: 'overview' | 'follow' | 'sea'
  northOpen: number
  finaleProgress: number
}
```

### 4.3 世界层

世界对象接收 `PointerState` 和 `WorldIntent`，只负责表现和局部运动：

```ts
wheat.update(pointer, intent)
girl.update(pointer, intent)
cameraDirector.update(intent, girl.position)
```

流程条件集中在 `StoryDirector`，不要在 `Girl.ts`、`WheatField.ts` 或 `Flowers.ts` 内部推进阶段。

## 6. Git 协作规范

### 6.1 分支模型

```text
main                 稳定、可现场演示的版本
develop              日常集成分支
feat/input           A 的输入与流程功能
feat/world           B 的世界与视觉功能
feat/show            C 的演出、UI 与发布功能
```

规则：

1. 不直接向 `main` 推送；
2. 功能从 `develop` 创建分支；
3. 一个分支尽量只解决一个半天到一天的功能；
4. 合并前至少由另一位成员 review；
5. 每天从 `develop` 生成一个可运行版本；
6. `main` 只接受已经从头跑通的 6 分钟流程。

### 6.2 提交信息

```text
feat(input): add hand lost fallback
feat(world): tune wheat wind response
feat(show): add finale camera transition
fix(flow): prevent phase transition on reset
refactor(core): split game loop from scene assembly
docs(team): add collaboration development plan
```

### 6.3 Pull Request 要求

PR 描述至少包含：

- 这次改了什么；
- 改动涉及哪些模块；
- 如何手动验证；
- 是否改变公共接口或配置；
- 是否需要其他成员同步调整。

合并前必须通过：

```bash
npm run typecheck
npm run build
```

并手动验证鼠标模式和摄像头模式至少各一次。

## 7. 开发阶段与里程碑

### 阶段一：0–3 小时，统一接口

三人一起完成流程表、状态机、模块边界、`PointerState`、`WorldIntent` 和分支规范。不要在接口未确定前大量做美术。

### 阶段二：3–10 小时，最小闭环

A 做最小输入，B 做可交互麦田和精灵，C 做占位 UI、镜头和计时。目标是“可以从开始走到结束”，画面可以先简陋。

### 阶段三：10–24 小时，模块深化

A 完善手势稳定性和阶段条件；B 完善 Shader、精灵、花朵和环境；C 完善镜头、音效、无文字引导和录屏模式。

### 阶段四：24–32 小时，接口冻结

第一次完整合并，之后不随意改公共数据结构。三人一起跑完整流程，记录卡点、误触发和节奏问题。

### 阶段五：32–40 小时，集中调体验

只调整颜色、风力、精灵速度、花朵时机、镜头速度、音效和结尾停留时间，不增加新玩法。

### 阶段六：40–47 小时，发布与排练

冻结 `main`，生成断网可运行版本，录制完整视频，准备鼠标兜底、设备接线方案和现场操作说明。

## 8. 日常同步机制

- 开工前 10 分钟：每人说明今日交付、涉及文件和潜在阻塞；
- 中途 5 分钟：只同步阻塞问题和接口变更；
- 收工前 20 分钟：三人运行当前版本，记录是否能跑通、最容易卡的阶段和第二天的冻结项。

接口变更必须在群里明确说明，例如：

```text
A：PointerState 新增 spread 字段，B 可从下一次合并开始使用。
B：今天不再修改 PointerState。
C：镜头只读取 phase=journey，不直接读取 flowers.remaining。
```

## 9. 验收清单

### 输入与流程

- [ ] 摄像头权限拒绝后能自动进入鼠标模式；
- [ ] 手离开画面 0.5 秒内不会瞬移；
- [ ] 捏合不会连续触发多次采集；
- [ ] 第一阶段不会永久卡住；
- [ ] `R` 可以完整重置体验。

### 世界与性能

- [ ] 手部动作在 1 秒内产生可见麦浪反馈；
- [ ] 精灵有跟随滞后和自主运动；
- [ ] 花朵有生长、采集、消失反馈；
- [ ] 视觉状态从冷灰平滑过渡到暖金；
- [ ] 目标设备上帧率稳定，无明显内存增长。

### 演出与发布

- [ ] 不看说明也能开始体验；
- [ ] 6 分钟内能到达结尾；
- [ ] 每个阶段都有明显视觉或声音变化；
- [ ] 最终高潮持续足够长，观众能看懂；
- [ ] 断网可运行；
- [ ] 有完整录屏和现场兜底方案。

## 10. 当前仓库协作注意事项

- `public/models` 和 `public/wasm` 是本地模型和运行依赖，不能删除；
- `npm run build` 中 Three.js chunk 较大的警告目前可以接受；
- 当前 `.playwright-cli/` 是本地测试产物，提交前确认是否应加入 `.gitignore`，不要把截图和日志混入功能 PR；
- 任何涉及 `App.ts`、`config.ts`、`types.ts` 的改动都应在 PR 描述中明确说明，避免隐性接口冲突。
